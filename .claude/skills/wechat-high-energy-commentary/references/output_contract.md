# Output & DOCX Contract

## Standard final package

For a selected or directly supplied topic, deliver:

1. **标题候选** — 3–5
2. **推荐主标题**
3. **摘要/副标题** — only when useful
4. **微信公众号正文**
5. **正文配图** inserted near relevant passages
6. **图注**
7. **图片来源**
8. **关键事实来源** — usually 5–10 load-bearing sources
9. **最终 `.docx`**

## Article length

- default: 2500–4500 Chinese characters
- “短一点”: 1500–2500
- “长文”: 4000–7000

## Source order

Prefer:
**official / primary → authoritative media → professional institution**.

When useful, annotate which claims are:
- confirmed facts
- analytical inference
- rhetorical/hypothetical devices

## DOCX layout

Optimize for editing and copy/paste into the WeChat backend:
- clean title hierarchy
- body text with short paragraphs
- minimal decorative Word effects
- images anchored simply and near relevant text
- captions immediately below images
- sources at the end
- no complex page furniture that makes copying difficult

## DOCX QA gate

When creating the Word file:
1. Follow the platform's DOCX creation skill.
2. Generate the `.docx`.
3. Render it to page PNGs using the canonical DOCX renderer.
4. Inspect **every page** at readable/100% scale.
5. Fix clipping, broken images, missing glyphs, bad spacing, awkward page breaks, or caption separation.
6. Re-render after fixes.
7. Deliver only after the latest render passes.

Unless the user requests intermediates, return only the final DOCX plus a concise completion note.
